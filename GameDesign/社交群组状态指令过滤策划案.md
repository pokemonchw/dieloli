# 社交群组状态指令过滤策划案

## 一、设计背景与目的
在当前版本中，不论玩家处于何种状态，界面底部默认会显示全部的指令类型分类（包含主动、对话、学习、娱乐等分类）以及各分类下的所有可用指令。
然而，当玩家加入场景内的一个社交群组（例如参与某一群人的“闲聊”、“上课”或“聚餐”）后，玩家当前的行为环境被限定。如果在“上课”群组中仍然显示“娱乐”、“主动（如买东西等）”等无关指令分类，会导致界面信息杂乱，降低沉浸感，且部分指令逻辑上不符合当前情景。

**本策划案目的：**
实现基于“当前社交群组活动状态（`session.type`）”的指令大类动态过滤机制。
当处于某一特定状态的群组互动时，仅呈现符合该情景逻辑的“允许显示的指令类型（白名单）”。同时，确保“系统（`SYSTEM`）”和“休息/脱离（`REST`）”相关的指令始终可见，以便玩家随时操作存档或退出社交群组。

---

## 二、核心实现逻辑

通过检测玩家当前角色状态和活动会话对象，来决定界面上具体展示的 `InstructType`（指令类型）：

1. **状态判定：**
   判断条件为：当前角色状态（`character_data.state`）等于 `constant.CharacterStatus.STATUS_SOCIAL_INTERACTING`，并且角色的当前群组会话 ID（`character_data.active_session`）不为空。

2. **获取当前群组的互动类型：**
   使用当前角色的 `active_session` 值，到 `cache.interaction_sessions` 字典中提取出对应的群组对象 `session`。
   获取 `session.type`，该值对应了 `constant.Behavior` 中的各类行为定义（如 `Behavior.CHAT` 闲聊, `Behavior.TEACHING` 教学等）。

3. **指令类型过滤（白名单机制）：**
   默认情况下渲染所有的 `InstructType`。一旦判定玩家在有效群组中，则初始化一个“指令类白名单集合”（默认仅包含 `InstructType.REST` 与 `InstructType.SYSTEM`）。
   然后通过判断 `session.type` 匹配规则，向该白名单中追加允许的指令大类（如对会上课情况追加 `InstructType.STUDY`）。
   在最后绘制UI列表（如 `Script/UI/Panel/in_scene_panel.py` 中的 `SeeInstructPanel`）时，对遍历过程进行一次拦截判断，不在白名单中的分类一律隐藏。

## 三、群组行为与指令类型映射表（规则详述）

根据现有的 `constant.Behavior` 行为和 `constant.InstructType` 指令类别，梳理出以下的映射过滤规则：

| 当前社交群组状态 (`session.type` / 对应行为) | 情景说明 | 允许显示的指令分类 (`InstructType` 白名单) |
| --- | --- | --- |
| `Behavior.CHAT` (闲聊) | 玩家与NPC正在聊天互动 | `DIALOGUE` (对话)、`REST` (休息)、`SYSTEM` (系统) |
| `Behavior.TEACHING` (教学) / `Behavior.ATTEND_CLASS` (上课) / `Behavior.SELF_STUDY` (自习) | 玩家正处于授课、听课或自习群组中 | `STUDY` (学习)、`REST` (休息)、`SYSTEM` (系统) |
| `Behavior.EAT` (进食) | 玩家在食堂/餐区与NPC一起聚餐 | `ACTIVE` (主动，含吃喝)、`DIALOGUE` (对话，吃饭时可聊天)、`REST` (休息)、`SYSTEM` (系统) |
| `Behavior.PLAY_COMPUTER` (玩电脑) / `Behavior.PLAY_PIANO` (弹钢琴) / `Behavior.PLAY_GUITAR` (弹吉他) / `Behavior.DRAW` (画画) / `Behavior.SEE_STAR` (看星星) / `Behavior.RUN` (跑步) / `Behavior.SHARE_BLANKLY` (发呆) | 玩家与NPC一起处于休闲/活动/娱乐群组中 | `PLAY` (娱乐)、`DIALOGUE` (对话)、`REST` (休息)、`SYSTEM` (系统) |
| `Behavior.ABUSE` (辱骂) | 处于争吵/校园霸凌等负面社交群组 | `DIALOGUE` (对话)、`REST` (休息)、`SYSTEM` (系统) |
| `Behavior.GENERAL_SPEECH` (演讲) / `Behavior.SINGING` (唱歌) / `Behavior.DANCE` (跳舞) | 处于表演、演讲及聆听状态 | `PERFORM` (表演/表现)、`DIALOGUE` (对话)、`REST` (休息)、`SYSTEM` (系统) |
| **其他未定义的群组行为 (兜底规则)** | 防止后续新增活动导致无指令可用 | `ACTIVE` (主动)、`DIALOGUE` (对话)、`REST` (休息)、`SYSTEM` (系统) |

*(注意：退出群组的指令若配置在主动(`ACTIVE`)或休息(`REST`)分类下，必须确保该分类能在对应状态下被白名单放行，否则玩家可能陷入无法脱离群组的逻辑死锁中。目前的规划统一包含 `REST`，如果“离开”指令在 `ACTIVE` 下，可酌情将其移至 `REST` 或将其单独过滤放行。)*

## 四、代码修改规划建议 (供程序参考)

### 涉及修改文件：
`Script/UI/Panel/in_scene_panel.py`

### 涉及类及函数：
`class SeeInstructPanel` -> `def draw(self):`

### 修改步骤细化：
1. **注入白名单获取逻辑：**
   在 `SeeInstructPanel.draw()` 函数内，提取玩家的角色数据，并前置初始化过滤集合：
   ```python
   character_data: game_type.Character = cache.character_data[0]
   allowed_instruct_types = set(constant.instruct_type_data.keys()) # 默认全量允许

   if character_data.state == constant.CharacterStatus.STATUS_SOCIAL_INTERACTING and character_data.active_session:
       session = cache.interaction_sessions.get(character_data.active_session)
       if session:
           allowed_instruct_types = {constant.InstructType.SYSTEM, constant.InstructType.REST}
           if session.type == constant.Behavior.CHAT:
               allowed_instruct_types.add(constant.InstructType.DIALOGUE)
           elif session.type in (constant.Behavior.TEACHING, constant.Behavior.ATTEND_CLASS, constant.Behavior.SELF_STUDY):
               allowed_instruct_types.add(constant.InstructType.STUDY)
           elif session.type == constant.Behavior.EAT:
               allowed_instruct_types.add(constant.InstructType.ACTIVE)
               allowed_instruct_types.add(constant.InstructType.DIALOGUE)
           elif session.type in (constant.Behavior.PLAY_COMPUTER, constant.Behavior.PLAY_PIANO, constant.Behavior.PLAY_GUITAR, 
                                 constant.Behavior.DRAW, constant.Behavior.SEE_STAR, constant.Behavior.RUN, constant.Behavior.SHARE_BLANKLY):
               allowed_instruct_types.add(constant.InstructType.PLAY)
               allowed_instruct_types.add(constant.InstructType.DIALOGUE)
           elif session.type in (constant.Behavior.GENERAL_SPEECH, constant.Behavior.SINGING, constant.Behavior.DANCE):
               allowed_instruct_types.add(constant.InstructType.PERFORM)
               allowed_instruct_types.add(constant.InstructType.DIALOGUE)
           elif session.type == constant.Behavior.ABUSE:
               allowed_instruct_types.add(constant.InstructType.DIALOGUE)
           else:
               # 兜底
               allowed_instruct_types.add(constant.InstructType.ACTIVE)
               allowed_instruct_types.add(constant.InstructType.DIALOGUE)
   ```

2. **拦截并跳过过滤类型（性能优化与UI拦截）：**
   **核心优化点**：由于判断指令可用性（前提条件 `handle_premise.handle_premise`）开销较大，应在生成指令列表并遍历前提之前就拦截掉被过滤的类型。
   在原本遍历 `constant.instruct_type_data` 的循环处进行修改：
   ```python
   # 原代码：for now_type in constant.instruct_type_data:
   for now_type in constant.instruct_type_data:
       if now_type not in allowed_instruct_types:
           continue  # 提前拦截，大幅节省指令条件判定开销
       instruct_type_data.setdefault(now_type, [])
       # ... 后续保留原有的指令遍历与前提判断逻辑 ...
   ```
   
   同时，在下方渲染标签页处同样进行过滤：
   ```python
   # 原代码：for now_type in cache.instruct_filter:
   for now_type in cache.instruct_filter:
       if now_type not in allowed_instruct_types:
           continue  # 隐藏不需要的指令分类按钮
       # ... 后续保留原有的标签按钮绘制逻辑 ...
   ```

### 异常及兼容性自测项建议：
- 加入群组后，测试是否能看到“系统”指令（正常存档和设定不受影响）。
- 确保测试“退出社交”类指令能在受限面板上被找到。
- 会话被强行打断（如对方死亡或NPC离场导致session解散）时，检查状态机和面板是否能正确重置为包含全部指令。
