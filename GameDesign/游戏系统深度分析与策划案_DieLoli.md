# 游戏策划案深度分析 - 《DieLoli (死亡萝莉)》

## 一、 游戏概述 (Game Overview)
*   **游戏名称**: DieLoli (死亡萝莉)
*   **游戏类型**: ERALIKE 文本驱动沙盒模拟游戏 (MUD / 涌现式模拟类)
*   **美术表现**: Ascii Art / 纯文本富文本交互界面
*   **核心开发架构**: Python 面向对象框架 + 字典树数据驱动
*   **游戏核心卖点**:
    *   **海量NPC自由演算**: 数千名NPC同时进行独立的运算，具有独立的需求、行动逻辑、社交关系和日程表，玩法接近《环世界》(RimWorld)、《矮人要塞》或文本版的《模拟人生》。
    *   **涌现式沙盒体验**: 游戏没有强制设定的主线任务，系统仅提供规则和物理状态计算，玩家与NPC的故事在极度自由的沙盒演算中自然发生。
    *   **大模型(LLM)深度赋能**: 内置 AI API 接口(支持本地 Ollama 部署和第三方如 OpenAI 接口)，允许使用大语言模型（如 DeepSeek）参与 NPC 逻辑与文本生成的动态反馈，突破了传统模板化文本的限制。
    *   **成人化与暗黑元素**: 包含深度的人类生理与心理模拟，涵盖色情、暴力等成人向要素 (Art is freedom)。

---

## 二、 核心循环与系统架构 (Core System Architecture)

游戏的核心采用 **基于效用(Utility)和状态机(State Machine)的 AI 系统**。在每次游戏的时间片流动时，系统会轮询所有角色的状态。

### 1. 行为与状态控制 (Behavior & State Machine)
*   **前提验证 (Premise)**: `Script/Premise` 目录构成了决策树的庞大判断库。系统会检查角色的身体状态（饥饿、性欲）、环境状态（是否上课时间、天气）、性格倾向，决定当前是否满足进行某种行动的前提条件。
*   **目标打分系统 (Target Score)**: `character_target_judge` 充当效用 AI 的核心。角色面临几十种可能的行为选项（闲聊、睡觉、进食、学习、性行为等），系统根据当前的 Premise 为各个 Target 权重打分，角色总是倾向于执行得分最高的目标。
*   **状态机执行 (State Machine)**: 一旦选定目标，角色的状态会被切换并挂载到 `Script/StateMachine` 对应的脚本中执行（如 `pathfinding` 寻路前往目标地点，`eat` 消耗食物恢复属性，`sex` 执行双人互动状态计算）。
*   **共计70余种精细状态**: 包括移动、上课、发呆、跳舞、手淫、数十种极为细分的肢体接触和性行为状态，确保模拟极度细致。

### 2. 角色数据模型 (Character Data Model)
角色被高度对象化，具有复杂的属性和生命周期：
*   **身份系统 (Identity)**:
    *   `StudentIdentity`: 拥有年级、班级、宿舍属性，受校园上课时间表约束。
    *   `TeacherIdentity`: 拥有办公室位置、负责科目，受课程表(`TeacherTimeTable`)强制约束。
    *   `ClubIdentity`: 涉及社团身份(社长/社员/顾问老师)，需要参与特定时间的 `ClubActivityData`。
*   **身体与成长**: 精准记录体脂率、身高、三围(`Measurements`, `Chest`)。身体数据会随年龄和饮食（营养摄入）发生动态增长与改变。
*   **知识与技能**: 设定了多语言和各学科的技能层级，通过 `study` 等状态机积累经验。

### 3. 社会、认知与人际关系网 (Social & Awareness)
*   **社会关系**: `social_contact` 保存不同关系等级下的角色集合（如恋人、暗恋、普通朋友、敌人）。
*   **动态认知系统 (`CharacterAwareness`)**: 游戏设定了极具创新的认知网络。角色获取其他人或事件的情报时带有“置信率(Authenticity)”。例如，如果听到同一种传闻(得到相同信息的计数 `got_count`)增加，该角色对该情报的置信度将呈10%递增。由此构筑了谣言、名声和极为真实的校园社会情报网。

## 三、 世界观与场景系统 (World & Scene System)

### 1. 基于拓扑结构的地图设计
*   **场景组织**: 场景由节点相连构成，包括室内室外标签 (`in_door`)。场景分类极为丰富：教室、食堂、社团活动室、宿舍等。
*   **动态寻路算法 (Dijkstra)**: 由于游戏世界拥有复数以上的节点，角色在决定去某个房间后，系统依赖预先运算的迪杰斯特拉算法快速分配移动耗时 (`Target_path`)，这保证了万人同服规模下的性能表现。

### 2. 时间表与社会秩序约束 (Time & Schedule)
*   **教师与学生课表**: `Cache` 中存储了精确到“星期X第Y节课的Z教室”的二维课程表。
*   **AI时间驱动**: 当时间到达上课点，学生和教师 AI 的行为效用打分发生剧变，群体将自动寻路至教室，实现如同真实世界的节律感。而下课时间，系统也会在食堂等设施重新分配角色的餐饮行为需求。

## 四、 大模型引擎赋能 (LLM Integration Engine)
这是本系统相较于传统 ERALIKE 游戏最大的技术护城河：
*   **架构解耦**: 传统的 ERA 游戏依赖预定义的文本库，而本作利用 `ai_run.py` 和 `ai_api.py` 在特定交互节点将角色的属性、当前状态字典转换为 JSON/Prompt 抛给外部接口。
*   **支持方案**: 完美支持本地硬件推理 (Ollama) 保障隐私与免费，也可挂载 OpenAI API 获取最强大的逻辑推演。
*   **定制化Prompt**: 用户可在 `config.ini` 自主编写 AI 的 Prompt 指令，决定 AI 在此沙盒下扮演“解说员”还是“角色第一人称”，拓展了二次创作的潜力。

## 五、 总结与产品建议

《DieLoli》并非一个传统的“游戏”，而是一个**高自由度的复杂社会群体仿真引擎**。
*   **优势**: 极致的AI细节（包括生理与认知），优秀的万人并发事件处理架构，且拥抱前沿的大模型技术。
*   **商业/技术潜力方向**:
    1.  **UI前端升级**: 目前纯依赖终端命令行的文本渲染，后续可通过 Web 技术(Vue/React) 或轻量引擎(Godot/Unity) 将后端这套无敌的仿真引擎进行 2D/3D 视觉化包装，将会是降维打击。
    2.  **异步AI运算优化**: 目前大模型 API 若同步调用会导致游戏卡顿(单次思考约需数十秒)。可设计为“异步请求”，在AI思考期间允许沙盒物理时间继续流逝，获取结果后利用“回忆”或“插入”形式展现，大幅度改善游戏流畅度。
