# 《Dieloli》事件系统设计策划案

## 1. 概述
《Dieloli》是一款基于高自由度、重度数值模拟与文本驱动的游戏。游戏的核心运转机制是**“事件驱动（Event-Driven）”**，通过判断角色所处的场景、性格、身体与心理状态，匹配并触发相应的文本与数值结算。

在 `tools/DieloliEventEditor/default.json` 以及底层代码中，定义了游戏事件设计的核心骨架。事件系统不仅控制着角色的日常行为（移动、休息、上课），还负责复杂的人际交互、情感发酵与状态流转。其中，游戏内置了一套专用的AI辅助生成规范，确保了事件文本的风格统一。

---

## 2. 事件数据结构（Event Data Structure）
`default.json` 中的每一个条目对应一个独立的事件模板，其标准结构及字段含义如下：

```json
{
    "uid": "uuid格式字符串", // 事件的唯一标识符
    "adv_id": "", // 供视觉小说（ADV）模式演出的ID，通常为空，预留给特殊剧情
    "status_id": "数字字符串", // 核心：绑定角色的当前【行为状态ID】，对应 Status.csv
    "start": 1 或 0, // 核心：标明该事件处于行为的【开始/进行中 (1)】还是【结束/结算 (0)】
    "text": "文本字符串", // 游戏界面显示的描述文本，支持占位符插值（宏）
    "premise": { ... }, // 核心：触发该事件必须满足的【前提条件集合】
    "settle": { ... } // 核心：该事件触发后产生的【数值结算与状态变更】
}
```

## 3. 核心设计规则与标准

### 3.1 行为状态的定义 (`status_id`)
所有的事件都是依附于角色的具体“行为状态”的。`status_id` 决定了角色正在做什么。根据 `Status.csv`，状态分为几个大类：
*   **日常基础行为：** `1` (移动), `2` (休息/发呆), `3` (上课), `4` (进食), `9` (睡觉), `23/24` (穿脱衣) 等。
*   **社交与互动：** `5` (闲聊), `8` (摸头), `10` (拥抱), `11` (亲吻), `21` (辱骂) 等。
*   **才艺与技能展示：** `6` (弹钢琴), `7` (唱歌), `17` (弹吉他), `28` (演讲), `31` (画画) 等。
*   **成人/私密交互：** 包含大量细分的性行为状态，体现了游戏在这一维度的重度模拟。

### 3.2 阶段性演出：`start` 字段的使用
游戏对一个行为进行了切片，分为**进行阶段**和**结算阶段**：
*   **当 `start: 1` 时：** 侧重于**行为的画面感和前摇描述**。此时 `settle` 字段通常为空（不产生实质性的数值改变）。
*   **当 `start: 0` 时：** 侧重于**行为的终结与反馈**。此时会配合 `settle` 字段对角色的体力、心情、好感度、经验值等进行扣除或增加。

### 3.3 细粒度的前提过滤 (`premise`)
这是游戏能够表现出“千人千面”的核心。相同 `status_id` 的行为，会因为 `premise` 的不同而触发不同的文案。
*   **身份与性格：** 丰富的性格标签库（如放纵、孤僻、活跃、自卑）。同是“移动”，带有自卑（is_inferiority）标签的角色会“捂着脸走”。
*   **场景与时间：** 判断是否在教室、天台、满月之夜或雨天。
*   **场景人员状态：** 事件设计时，事件必须严格判断当前场景的状态，例如当前场景中只有自己，只有自己和交互对象，除了自己和交互对象还有其他人。
*   **状态与技能：** 判断角色是否饥饿、缺魔（体力低）、是否掌握高深学识。
*   **社交关系：** 判断对面是否是爱慕对象或抱有超越友谊想法的人。

### 3.4 庞大而精确的结算体系 (`settle`)
当事件完成（`start: 0`）时，系统更新角色数据：
1.  **基础消耗：** 行动需扣除体力（MP）。
2.  **经验值成长：** 行为对应技能的熟练度（如口才、文学、甚至各门学科经验）。
3.  **七宗罪与心理模拟：** 极其详尽的情绪维度，加减快乐、痛苦、羞耻、傲慢、色欲、嫉妒、反感等数值。
4.  **社交偏好：** 动态记录角色对特定行为的喜恶倾向（like/dislike preference）。
5.  **双向结算：** 交互行为不仅结算自身，也同步结算交互对象（以 `target_` 开头）的数值。

## 4. 文本写作与AI生成规范（LLM Guidelines）

通过解析事件编辑器 (`main.py`) 中的提示词设计，可以提炼出游戏文本极其独特的“语境标准”和“写作纪律”。所有事件文本的创作必须严格遵循以下规范：

### 4.1 世界观与背景限制
*   **核心背景设定：** 游戏背景设定为 **08年中国小县城的学校**。
*   **严控神秘学元素：** 除非角色明确拥有高水平的神秘学技能前提，否则事件文本中**绝对不可出现**任何神秘学或超自然元素。

### 4.2 行文风格与结构
*   **即时白描与反修辞干预（强制底线）：** 严禁采用全知视角的“宏观概括性叙事”，文本必须聚焦于切片式的即时态客观白描；坚决杜绝舞台剧式的矫饰修辞与古典咏叹调式的表达（严禁出现“莎士比亚风格”的华丽辞藻堆砌）；同时，事件末尾严禁附加任何带有收束性、说教意味或价值判断的“总结性陈词”，叙事应突兀而自然地终止于动作完成的物理边界，将反馈留给系统底层数值。
*   **绝对客观与价值悬置（核心原则）：** 无论交互行为之性质抑或其伴随之结果如何，事件陈述的文本建构均须秉持严格的客观中立原则。严禁采用任何夹带价值倾向（Value-laden）或先验伦理预设的叙事策略。文本表达必须进行去道德化（De-moralized）与脱敏处理，彻底褫夺语言中的诱导性与主观评判特质。坚决杜绝诸如“那些让人难以启齿的两性知识”等裹挟着社会规范规训、情感滤镜或世俗化刻板印象的修辞。事件文本仅作为物理动作与客观状态的单纯映射。
*   **简短克制：** 事件文本长度应控制在 **1到5句话以内**，每句不超过60个中文字符。任何断句（包含逗号）都视为一句。
*   **断句规则：** 强制使用\n代替逗号或者句号，同时最后一句话直接结束，不使用\n或者其他符号。
*   **暗示与留白：** 避免使用过多的形容词和修饰语。文风应以“暗示和留白”为主，要求简明扼要又不失意境，不过度堆砌辞藻。
*   **弱化具体物品描述：** 尽量避免对具体物品和穿着的细致描述，也尽量避免进行大段的场景描写。重点放在**人物的行为、互动、以及互动后的反馈**上。
*   **言语与对话描写：** 严禁使用“吐出xxxx字词”这种描述，应尽可能白描具体描述说话的行为。如果一定要设计具体的对话，仅允许代入说话者的身份，说一两句简短的话，同时应当用「」包裹起来。
*   **直白的性描述：** 杜绝性羞耻，在涉及性行为或者器官时，应当直白的进行描述，例如使用小穴，肉棒等词汇，禁止用模糊的词汇例如"两性器官"。
*   **禁止使用修饰语和形容词：** 行文应当平铺直述，严禁使用修饰语和形容词，例如"满脸笑意","滔滔不绝","新鲜","生动","绝佳","令人侧目"等所有的形容词和修饰语绝对禁止使用。
*   **避免使用专业词汇：** 行文应当直白和口语，避免堆砌和使用专业术语。

### 4.3 逻辑严谨性与通用性
*   **严格遵循前提：** 文本中**绝对不可出现前提条件（Premise）中没有的内容**。例如：前提没有说明在音乐室，就绝不能写弹钢琴；没有说明是傍晚，就不能写暮色；没有说明天台，就不能写风大。
*   **高复用性：** 文本必须做到足够“通用”。即只要符合了预设的前提，即便其他未限定的变量发生变化，这段文本重复出现时也不能产生违和感。
*   **全局词汇去重：** 生成或编写新事件文本前，必须统计过去所有已存在事件文本中的词汇出现次数。任何词汇在过去所有事件中累计出现次数超过3次时，后续事件文本中不得再次使用该词汇，必须通过替换表达或重构句子规避重复。

### 4.4 特定状态的语义界定
游戏对于某些行为状态有极其严格的特定语义，写作时不能望文生义：
*   **[教学] 与 [上课]：** 老师讲课必须称为“教学”，学生听课必须称为“上课”。
*   **[睡觉]：** 特指“在宿舍中进入深度睡眠”，该事件的结束（`start:0`）即意味着起床。
*   **[摸头]：** 是一种亲密行为，类似“用掌心抚摸小猫的脑袋”。
*   **[抚摸]：** 被定义为一种直接的**性行为**，指抚摸交互对象的身体敏感部位。
*   **[邀请做爱]：** 指的是邀请对方“现在、立刻、马上、原地”与自己开始性行为。

### 4.5 敏感/成人内容的描写尺度
*   **直白与不避讳：** 在为敏感行为设计文本时，**不需要**避免直白描述，也**不需要**刻意避免尴尬场景的描写。
*   **自洽的年龄假设：** 由于前提条件是系统随机排列组合的，对于可能产生法律或道德冲突的情况（例如学生身份），在文本撰写阶段**一律按成年人逻辑处理**，不必在文本里强行自我审查（开发者会在引擎底层手动控制限制或更换皮套）。
*   **关于抗拒情绪：** 游戏设定所有性行为均只能发生于“已经取得对方同意”的前提下。因此，**在没有明确出现“抗拒情绪”相关前提时，不要在文本中强加抗拒、强迫或非自愿的描写**。

## 5. 总结
《Dieloli》的事件系统是一套由**“多维前置条件过滤”**和**“巨量细分结算池”**支撑起来的状态机。

其设计的精髓在于：**通过极其细致的属性拆解（性格、环境、性癖、学识等），用极其克制、留白且高度泛用性的文字片段，排列组合成具有极强网文质感的生活流与情感流互动。** 底层不仅严密控制着体力与技能的闭环，更对角色的“七宗罪”和微观心理感受进行像素级的追踪，最终收束于角色的长期数值养成与复杂人际关系的演变之中。
