# 系统策划案：大模型(LLM)驱动与UI表现系统

## 一、 系统概述
此系统是《DieLoli》在技术层面的最大创新点。它彻底改变了 ERALIKE / MUD 类游戏长期受限于人工预设文本模板的困境。通过结合富文本终端输出与大语言模型（如 DeepSeek、OpenAI 等），游戏实现了“无限剧本”和高度沉浸的互动。

## 二、 大模型接入引擎 (LLM Integration)

### 1. 接口与架构设计 (`ai_run.py`, `ai_api.py`)
- **双模式运行环境**：
  - **本地 Ollama 推理**：允许玩家利用本机显卡（如 RTX 3060 以上）运行 `deepseek-r1:1.5b` 等轻量化模型。优势是完全本地化无网络延迟，数据安全。
  - **远程 API 推理 (Base_URL + API_Key)**：接入商业模型，获取更强大的逻辑分析与长文本撰写能力。
- **上下文封装 (Prompt Engineering)**：
  - 核心设计在于将游戏内部繁杂的数据结构（如对象的当前动作、环境、历史交互记录、甚至性格特点）转化为自然语言字典。
  - 组装成包含 System Prompt 的完整上下文后，请求 AI 为当前行为“润色文字”或“产生决策反馈”。

### 2. 难点与现行解决方案
- **性能卡顿问题**：目前的生成属于同步/半同步阻塞。作者在 README 中提到“思考20s左右”。
- **Prompt 热更新**：玩家可通过修改 `config.ini` 中的 Prompt 配置，自由决定大模型的发音口吻或行文尺度（绕过某些云端接口的安全审查限制或做特定的世界观转换）。

## 三、 富文本与命令行UI (Rich Text UI)

### 1. 富文本对象封装 (`rich_text.py`)
- 抛弃了简单的 `print()`，构建了精密的终端光标控制和多颜色字符渲染。
- 支持类似于前端 HTML `<span>` 的行内多属性渲染：同一行内不仅有各种颜色区分（如人物名粉色，场景提示灰色），甚至可以将文字直接挂载为“可点击的事件按钮” (`is_button`)。

### 2. 地图渲染与主视图 (`main_frame.py`, `MapDraw`)
- **空间渲染**：利用 ASCII 字符构图。`MapDrawLine` 和 `MapDrawText` 负责计算终端屏幕宽度，绘制出结构化的场景视图。
- **交互控制**：利用系统的鼠标/键盘监听事件 (`WFrameMouse`) 捕捉玩家鼠标坐标，映射回文本按钮实现零 UI 框架的交互点击，极其复古又极其硬核。

## 四、 拓展与优化建议

### 1. 彻底的异步消息流 (Asynchronous AI Stream)
- 引入类似于前端流式输出 (Stream: true) 的机制。在请求 LLM 回复时，只显示“正在思考/打字...”的效果。同时在后台采用 `asyncio`，允许游戏的时钟(Tick)在 AI 计算期间继续推进物理运算，杜绝游戏挂起（画面卡死）的现象。

### 2. LLM 代理决策层 (Agentic Layer)
- 目前 AI 主要负责润色交互表现。可以开放更高权限——当处理“玩家直属女主角”的重要人生分歧时，将好感度、各种选项一并交给大模型，让 LLM 而非简单的数值判定来决定女主角的回复，彻底实现真正的“AI伴侣”。
