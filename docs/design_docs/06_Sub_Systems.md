# 扩展与子系统模块

为了丰富游戏世界的真实感和可玩性，游戏中包含了多个完全独立但也与主框架深度耦合的子系统。这些子系统多位于 `Script/Design/` 目录下。

## 1. 烹饪与食物系统 (`cooking.py`)
类似于《塞尔达传说》或《模拟人生》的食物机制。
* **食材与配方**：游戏内定义了多种基础食材。玩家或 NPC 可以在具有厨房设施的节点进行烹饪。
* **食物属性**：烹饪出的食物带有饱食度恢复、水分恢复，甚至可能有隐藏的正面/负面 Buff 属性。
* **NPC 饮食逻辑**：当 NPC 饿了，寻路去食堂时，食堂的“食物池”会为他们提供随机的餐食，这会直接影响他们接下来的状态流转。

## 2. 社团与课程系统 (`club_handle.py`, `course.py`)
这是构成校园生活的基础骨架。

### 2.1 课程系统 (Course)
* NPC 生成时（若是学生），会被分配年级和班级。
* 每天在特定的时间段（如早上 8 点），状态机发现时间满足上课前提（Premise），且其状态为学生，就会强制把他们的寻路目标设为各自的教室。
* 上课行为（Settle）会扣除精力，增加学识。

### 2.2 社团系统 (Club)
* 丰富课后生活的机制。社团有独立的据点（地图节点）。
* 角色可以加入社团，在下午的特定时间段，状态机会驱使他们去社团进行活动。
* 社团活动能够增加特定的兴趣爱好属性，同时也为同社团的 NPC 创造了聚集在一起产生交互事件的契机。

## 3. UI 交互系统 (`Script/UI/`)
由于游戏底层放弃了原生终端，这里构建了一套基于面板 (Panel) 和 流程 (Flow) 的 UI 管理体系。
* **Panel (面板)**：负责静态 UI 元素的排版。比如 `game_setting_panel.py`（设置界面）、`character_info_panel.py`（角色属性查看）。面板代码只负责生成带有颜色的富文本标签。
* **Flow (流程)**：负责处理交互逻辑。当玩家点击 Panel 上的某个按钮时，会触发对应 Flow 中的函数，处理数据变更后，Flow 会请求 Panel 重新渲染。

## 4. 成就系统 (`handle_achieve.py`)
* 用于记录玩家或整个游戏世界达成的某些极端/稀有条件。
* 支持多档位判定，达成后可能给予全局性的加成或者解锁新的开局特质。

---
> 所有的子系统都可以通过增加或修改 `data/csv` 中的配置来进行扩展。在添加新模块时，必须遵循：`注册前提条件 (Premise) -> 注册行为逻辑 (StateMachine) -> 编写结算公式 (Settle)` 这一标准的数据驱动流线。
