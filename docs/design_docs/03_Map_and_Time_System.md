# 地图、时间与环境系统

这部分构成了游戏运转的空间和时间基础。

## 1. 游戏地图与寻路 (`Script/Design/map_handle.py`, `Core/dijkstra.py`)
由于每个 NPC 都有独立的实体位置，因此游戏拥有一个抽象的节点化地图结构。

* **地图抽象**：地图是以 `节点 (Node)` 与 `连线 (Edge)` 构成的有向/无向图结构。定义在 `data/map` 或相关配置中。
* **角色移动**：当 NPC 需要去食堂吃饭时，系统会使用经典的 **Dijkstra 算法** (`dijkstra.py`) 寻找当前节点到目标节点的最短距离。
* **场景限制与隔离**：不同的场景（如男更衣室、女洗手间）带有严格的进入许可（`Premise` 前置条件）。如果强行进入，会引发特定的越界行为判定。
* **位置管理**：`map_handle.py` 记录了哪个地点当前有哪些角色，这是为了方便玩家或其他 NPC 探测到同一空间内其他角色的存在，从而引发交互事件。

## 2. 时间流动系统 (`Script/Design/game_time.py`)
时间不是连续平滑的，而是被分割为“分钟/刻/小时”等离散单元（类似于回合制）。

* **时间的最小单位**：时间的推进通常由玩家的行动或点击“等待”按钮引发。每推进一分钟，全局的系统时间增加。
* **全图演算驱动器**：时间的推移是驱动 NPC 行动的唯一马达。当时间增加时，系统会广播更新信号，触发全部 NPC 检查自己当前的任务是否过期，并重新结算各种状态属性（如随时间增加的饥饿、精神疲劳等）。
* **季节与节日**：内置了日历系统，支持四季的轮换。季节会影响天气，部分特定日子（如情人节、圣诞节）会引发系统预设的特殊 Event。

## 3. 天气系统 (`Script/Design/weather.py`)
* **动态天气**：晴天、雨天、雪天等。
* **效果联动**：天气不仅是一段文本描述，还会直接影响环境结算。比如雨天如果在没有遮挡的室外移动，会增加角色的“湿润度”和“寒冷值”，进而可能引发“感冒”的负面 Status 判定。
