# 状态机与 AI 系统 (Script/Design/character_behavior.py, ai_api.py)

在没有玩家主动下达指令时，数千名 NPC 依然在生生不息地运作，这依赖于其背后的 AI 与状态机系统。游戏支持传统的决策树 AI 和 基于强化学习的外部 AI。

## 1. 基础状态机流转 (State Machine)
这是 NPC 默认的行动依据。由 `tools/buildstate.py` 编译生成的 `Script/StateMachine/` 模块执行。

### 1.1 需求层次理论 (Needs Hierarchy)
NPC 的行为动机很大程度上参考了马斯洛需求层次：
* **生存需求**：最高优先级。当饥饿、口渴、尿急达到极高阈值时，NPC 会立刻放弃当前所有动作（打断当前流程），强制将寻路目标设定为餐厅、厕所或宿舍。
* **社会与日常需求**：如果没有生存危机，NPC 会根据当前的“日程表”进行活动。比如学生上午去教室上课，下午可能去社团 (`club_handle.py`) 或在校园闲逛。

### 1.2 行为结算与状态流转 (`settle_behavior.py`)
* 当 NPC 抵达目标地点后，会执行对应的“动作”。
* 动作完成后，调用 `Settle` 结算系统：修正 NPC 自身的各项属性（如上课增加智力，吃饭降低饥饿）。
* 结算完毕后，状态机判断其该进入下一个什么状态（闲置、移动到新地点、或者找人对话）。

## 2. 基于强化学习的 AI (RL Engine - `ai_api.py`)
这是一种为了提升游戏深度的“实验性”功能。它将游戏变为一个 HTTP 形式的开放环境 (RL Environment)。

### 2.1 HTTP 环境接口设计
游戏在后台启动了 HTTPServer 暴露在 `5000` 端口：
* `/state` (GET)：获取当前游戏内某一特定 NPC 或全图的精简环境向量状态。
* `/actions` (GET)：获取当前 NPC 合法可执行的动作集合。
* `/actions` (POST)：接收外部传来的指令。
* `/rewards` (GET)：基于游戏内的特定目标（例如存活天数、与其他角色关系度提升）返回即时奖励值。

### 2.2 模型调用 (`ai_run.py`, `policy_model.pth`)
* 如果启用了内部的 AI 决策模式，游戏会自动加载 `data/policy_model.pth` 这个基于 PyTorch 训练出来的多层感知机或策略网络。
* 它可以替代一部分传统的硬编码状态机逻辑，让某些高光角色的行为更难以预测、也更符合复杂的利益最大化原则。

## 3. 大语言模型文本生成 (LLM Narrative)
* 本质上是一个“文本润色”外挂。
* 当状态机判定某个行为发生时（比如 A 扇了 B 一巴掌，因为 B 性骚扰 A），游戏只知道抽象的事件定义。
* 开启此功能后，引擎会将抽象事件（人物A，动作：扇耳光，对象B，前提条件：愤怒、被骚扰）组合成 Prompt。
* 通过 `ollama` 或 OpenAI API，实时生成一段短小精悍的过渡小说文本显示在 UI 上，使整个沙盒世界变得像一部实时连载的小说。
