# 事件系统与数据驱动流水线 (Events & Data Pipeline)

DieLoli 摒弃了传统的硬编码游戏逻辑，转而使用了类似“配置即代码 (Configuration as Code)”的数据驱动流水线设计。

## 1. 核心编译机制 (`tools/build*.py`)
为了兼顾“便于策划和 Mod 创作者编写”与“极高帧率的执行效率”，项目建立了一套完整的构建管道。

### 1.1 数据源格式
在 `tools/` 目录或编辑器中，开发者维护的是简单的 `CSV` 文件，如：
* `premise.csv` (前提条件)
* `state_machine.csv` (状态机转移逻辑)
* `Settle.csv` (结算结果公式)

### 1.2 Python 代码生成
* 游戏并不是在每次运行或每帧去读取解析这些体积庞大的 CSV。
* 开发者在修改 CSV 后，必须手动执行 `buildstate.py`, `buildsettle.py`, `buildskill.py` 等脚本。
* 这些脚本会逐行解析 CSV，并运用 Python 的 AST (抽象语法树) 逻辑或字符串拼接，直接输出原生的 `.py` 脚本到 `Script/Premise/`, `Script/Settle/` 和 `Script/StateMachine/` 目录。
* **优势**：游戏运行时执行的是原生的 `if/else` 与字典查找，运行速度极快，足够支撑上千 NPC 的高频逻辑判定。

## 2. 前置条件系统 (`handle_premise.py`)
这是行为发生的看门人 (Gatekeeper)。
* 任何一个动作（包括玩家选择的动作指令和 NPC 试图执行的动作），在执行前都会调用被编译好的 `Premise` 校验函数。
* 校验范围极其广泛：检查自身属性（体力是否足够）、检查环境（是否下雨）、检查目标状态（对方是否睡着）、检查物品（是否持有特定道具）等。

## 3. 动作与事件结算 (`event.py`, `settle_behavior.py`)
当 Premise 验证通过，动作被确认执行时：
1. **执行结算 (Settle)**：系统调用 `Settle` 模块对双方/环境进行数值修改。比如进行“授课”动作，会减少教师的体力，增加学生的知识度和疲劳度。
2. **触发事件 (Event)**：`event.py` 是用来捕获那些由于属性剧烈变化或特定组合引起的“特殊剧情”。
   - 例如：如果学生的“压力值”结算后超过阈值，可能会打断正常逻辑，触发一个“情绪崩溃”或“离校出走”的事件。
   - 事件触发时，可以通过调用 UI 层强制弹出对话框，甚至中断当前流程流转。
3. **调用 AI 润色**：在此环节，如果检测到符合配置要求的事件，则会自动请求大模型（Ollama 等）为这一连串机械的数值结算生成一段人类可读的文学描写。
