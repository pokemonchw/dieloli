# 引擎核心层 (Script/Core)

引擎层（基于原有 Pyera 的大幅改造版）是 DieLoli 脱离系统终端限制、实现高自由度的基础。它主要负责窗口渲染、输入捕获、多语言处理以及游戏状态的持久化。

## 1. UI 渲染框架 (`main_frame.py`)
这并非一个标准的系统终端，而是一个利用 **PySide6 (Qt)** 实现的终端模拟器应用。

### 核心特性
* **自定义布局管理**：窗体拆分为多个区域（主文本显示区、侧边栏信息区等），利用 Qt 的 `QVBoxLayout` 和 `QHBoxLayout` 进行编排。
* **富文本处理**：使用 `QTextEdit` 并深度定制了渲染逻辑，支持复杂的图文混排、自定义颜色标签，这是原生终端无法比拟的优势。
* **事件解耦**：UI 线程不直接调用业务代码，所有的交互（点击按钮、回车输入）会被打包为特定指令，通过队列 (`Queue`) 传递给游戏主逻辑线程。

## 2. 流程与输入分发 (`flow_handle.py` & `io_init.py`)
游戏是一个“等待输入 -> 处理并结算 -> 重新渲染等待输入”的过程。

* **`io_init.py`**：负责建立并维护输入与渲染的通讯机制。它包含了 `_send_queue` (发送给 UI 渲染的队列) 和 `_order_queue` (从 UI 接收的玩家操作指令)。
* **`flow_handle.py`**：负责拦截和分发这些指令。业务层会向 `flow_handle` 注册当前期待的输入回调，当匹配的指令到达时，触发相应的流程代码。

## 3. 缓存与持久化 (`cache_control.py`, `save_handle.py`, `game_type.py`)
这是整个游戏的“内存”和“硬盘”。

* **`game_type.Cache`**：定义了所有游戏内运行时需要保持的数据结构（如人物字典、地图缓存、当前时间、俱乐部状态等）。
* **存档机制**：使用 `json` 进行序列化存储，但面对庞大且复杂的对象（数千个 NPC），它实现了一套高效的增量、序列化逻辑，确保存档体积与读写速度在可控范围。

## 4. 国际化支持 (`get_text.py`)
DieLoli 包含了原生的多语言框架，使用经典的 `.po` / `.mo` 方案 (GNU gettext 标准)。
* 利用 `polib`，框架可以在运行时快速加载编译好的 `.mo` 字典。
* 通过全局函数 `_()` 将 UI 字符串或配置表内的字符串替换为当前语言（如 `zh_CN`, `en_US`）。
* 在构建阶段，会自动提取所有需要翻译的词条并打包。
